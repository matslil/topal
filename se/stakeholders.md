# Stakeholders

## TOPAL-STK-001 — Language users

People writing application, systems, and hardware-facing Topal code need clear
semantics, useful diagnostics, safe composition, and predictable execution.

## TOPAL-STK-002 — Library authors

Authors of reusable abstractions need stable contracts, generic composition,
coherent capability evidence, and compatibility across language revisions.

## TOPAL-STK-003 — Tool implementers

Independent compiler, interpreter, linter, debugger, and analysis-tool authors
need precise, testable specifications and interoperable representations.

## TOPAL-STK-004 — System integrators

Integrators need explicit effects, layouts, protocols, serialization, resource
rules, and boundaries suitable for external systems and hardware.

## TOPAL-STK-005 — Language maintainers

Maintainers need traceable design evolution, machine-checkable rules where
practical, and evidence that tools continue to implement approved intent.
