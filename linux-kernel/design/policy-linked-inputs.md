# Complete linked inputs for finite and numeric policy objects

`TK-DEC-274`; systems-only implementation of the existing immutable code binding
and closed source/runtime obligations in `TOPAL-SYSTEMS-SOURCE-LIBRARY-001`,
`TOPAL-SYSTEMS-NUMERIC-RUNTIME-001` and
`TOPAL-SYSTEMS-KERNEL-POLICY-BINDING-001`. Standing systems authorization applies;
ordinary language meaning, source interfaces and native entry ABIs remain intact.

## Confirmed gap and scope

The first finite/numeric bindings inspect source/object provenance, function
presence/placement and resource certificates. Unlike the later region bindings,
they do not independently compare all actual linked instruction and immutable
input bytes with a publisher-owned binding.

Independent checks of the earlier numeric deadline artifact change the actual
Nat literal 10 to 11, or replace the first instruction byte of an ordinary
numeric helper, preserving source snapshots, symbols and inner bindings and
correcting only the outer kernel digest. The earlier boot packager accepts both
images. These are packaging counterexamples; neither altered image is claimed
to execute successfully. The literal lies outside the already qualified Unit
and action data sets.

The finite policy object's immutable section includes actual linker relocations
for a jump table. Binding only named numeric literals, or assuming all immutable
bytes are relocation-free, would miss that input. This increment covers the
finite slot and each selected numeric slot: time, image header, dispatch and
process identity. Existing stronger Unit/action bindings remain unchanged.

## Object-owned sections and linked comparison

Inspect every nonempty allocated section of the compiler-owned policy object.
Reject writable/TLS storage, unsupported allocated kinds/flags and ambiguous
identities. Retain executable text and read-only data, including anonymous
tables, zero bytes and padding. Record each complete section's stable ordinal,
original name, exact size/alignment, executable role and unlinked byte digest.
The existing source/frontend, complete function/call, native instruction,
undefined-dependency and resource checks remain mandatory.

Use the already required LLVM object-copy tool to give each retained section a
slot-qualified private name and local begin/end marker symbols. These symbols
grant no source-visible address or authority. Remove constant merging/string
coalescing flags on these sections so every object-owned extent remains intact;
do not change payload bytes, relocation meaning, function identity, ordinary
debug strings or native entry ABI. Verify the transformed object's complete
allocated-section set, bytes, roles, sizes, alignments and marker endpoints.
Publish the digest of that actual transformed object. An object without
read-only data is valid when its executable sections remain complete.

After normal linking, inspect each pair of local markers exactly once. Require
the same section and an exact bounded extent, alignment and executable role in
the active supervisor envelope. Bind the actual relocated bytes, including
resolved calls, addresses and jump-table entries, together with the selected
object digest and complete ordered section manifest. Require disjoint extents
within each policy binding. The publication binding is absent in an unlinked
object certificate and mandatory in a linked systems artifact.

Boot packaging repeats that inspection and compares the complete result to the
publisher-owned binding. Reject missing/extra, reordered/duplicate, wrong-slot,
wrong-object, changed extent/address/role/bytes and incompatible metadata. The
actual private marker namespace must equal the complete expected set. Absence
of a policy slot requires absence of its markers. A corrected outer kernel
digest cannot substitute for this comparison. Atomic failure leaves no new
artifact directory. This is provenance/consistency checking, not authentication
against a party able to replace all source and inner provenance together.

## Alternatives and compatibility

Per-definition named immutable data remains suitable for Unit/action profiles.
It does not directly cover LLVM's anonymous relocated finite-policy tables.
Hashing the whole final read-only segment would conflate unrelated objects and
would not prove each source object's complete input set. Object-owned section
boundaries cover the complete code/data contribution while retaining ownership
and supporting the target linker's normal relocations. Recompiling source during
boot packaging would add an unnecessary compiler dependency to that boundary.

Advance finite object metadata to schema 3 and numeric metadata to schema 9;
retain native entry ABI, machine/allocation certificate meanings and all caller,
stack, arena, retained-state and cleanup obligations. Advance current aggregate
artifact/boot qualification identities. Old incomplete metadata cannot masquerade
as a new complete binding. Immutable section placement may change because the
linker no longer coalesces these objects' inputs; source value bytes and public
Linux behavior remain unchanged. AArch64 and RISC-V require the same complete
object/linked obligation with their separately qualified formats and relocations.

## Qualification and risk

Reproduce the actual literal and code-byte counterexamples as boot refusals with
only the outer kernel digest corrected. Cover every selected slot, actual finite
jump-table bytes/relocations, valid objects without read-only data, complete
marker/manifest closure and malformed metadata. Keep independently rebuilt source
variants valid; a changed source body must still alter actual source behavior.
Requalify all current VM cases, ordinary helper frames, complete resource proofs,
caller/state preservation, cleanup and unmodified BusyBox workloads.

Risk is high at object-to-linked closure, relocation preservation, section
placement and private-format compatibility. Review authoritative immutable code,
closed source/runtime, resource and ABI intent; inspect the independent byte
counterexamples, complete manifests, marker ownership, strict refusals and actual
physical execution. Human PR review remains required. This increment updates
the single existing Step 4 PR and does not establish general Linux compatibility.
