# Provider-owned traversal hooks

This implements the next part of `TK-DEC-282` Stage 2 under standing systems-only
authorization. Ordinary source algorithms and their value/effect meaning remain
unchanged. The provider supplies freestanding context, value-transfer, allocation
and scoped-loan hooks; independent C code remains an observer/test controller.

Rebuild the source component and generate an exact private layout and readonly
tables for root kinds/offsets/extents, helper identities, region parameters and
closed call edges. Count actual control/frame records, both banks, source work,
allocation-start provenance, result, padding and per-step budgets. Include the
64-byte recovery header and eight-byte instance cell under the existing 65536
temporary reserve. Stack costs need separate linked target evidence under the
4096-byte reserve; a fitting data layout is insufficient.

The reached LLVM provider hooks have no host allocation, libc, syscall or callback
dependency. They use the bound active boundary record to identify the exact
context and persistent history before accessing private fields. Exact source
entry, owner/generation, active/fatal state, current frame/view and complete
numeric provenance are checked. Immutable constants are accepted only through
the generated source component's exact readonly-root query. No numeric range
or pointer equality creates storage ownership.

Each allocation is aligned and recorded before reuse; roots may reference only
issued work objects, current bank starts or exact readonly objects. Copy validates
the complete integer sign/length/limbs and target classifier/width. Helpers issue
fresh frame/loan identities and revoke their entire descriptor at return. Root
replacement and checkpoint retirement remain a controller obligation after all
source/helper frames return. Per-step and invocation identity budgets are both
enforced; physical descriptor reuse never resets persistent history.

For the runtime-bound boundary variant, the live recovery header additionally
pins the owning caller's persistent history before source entry. Admitted source
abort or invalid machine outcome marks that domain fatal/inactive before erasing
private storage and entering the bound nonreturning fatal handler. Source context
corruption cannot substitute a different history pointer. Between-step cancellation
uses the owning controller's separately retained resource facts. Existing boundary
components retain their earlier exact ABI and behavior.

The first hook component still requires owning-caller admission and mapped,
exclusive, disjoint owner/history/temporary/stack/input extents. A test initializer
does not qualify a kernel callsite. Normal completion, controller scratch/register
retirement, exact code/data/hook closure, interrupt context and actual kernel owner
integration must be bound before executable publication. Tests may inspect a
nonreturning failure through an observer escape; that escape is not kernel recovery.
AArch64/RISC-V need their own target layout/calling-convention/context providers.
