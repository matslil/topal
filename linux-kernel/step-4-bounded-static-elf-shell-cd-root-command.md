# Step 4 increment: bounded static-process shell root `cd`

## Outcome

This increment inserts exact `cd /\n` between the qualified `echo topal\n`
and `pwd\n` commands. Both profiles consume four ordered publications through
one checked command buffer, issue native x86-64 `chdir` for an application-
owned exact `/\0` candidate, replace the sealed current-directory generation,
and prove the following `pwd` observes root before exact `exit\n` teardown.

The clean fixture publishes four prompts and performs a fresh command-time
`getcwd`. Pinned BusyBox keeps prompts absent, revalidates stdout metadata and
terminal absence, and formats `/\n` from the replaced sealed-root fact. The
extra built-in moves BusyBox's formatting buffer, so the external output
contract validates the complete two-byte candidate within the already sealed
readable heap mapping instead of inheriting an incidental single address. Its
bytes, count, result, staging, ownership, and ordering remain exact.

## Risk and remaining boundary

Risk is high because a real application mutates process filesystem state and
shifts an application-owned output candidate while all transfer, observation,
and teardown authority must remain bounded. Review combines exact profile,
predecessor, pathname, mapping, result, generation, ownership, output, prompt,
terminal, rollback, and physical runtime evidence.

This proves one idempotent root-directory change. It does not provide arbitrary
pathnames, lookup, mutable directories, a general command loop, dynamic
applications, multiple processes, containers, or VM-host support.
