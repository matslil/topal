# Step 4 fault-contained `copy_to_user` and `uname` increment

## Outcome

The checked systems root now admits one pointer-bearing Linux x86-64 syscall.
Its source-owned `new_utsname` value is copied through an affine user-transfer
scope tied to the exact process, address space, thread, ABI, and syscall entry.
The generated probe verifies both a complete `uname` transfer and `-EFAULT`
after a second transfer crosses into an unmapped guard page.

This remains a systems-feature extension. An untrusted user candidate never
becomes a Topal reference, ordinary source cannot install a recovery address,
and no core-language expression, reference, or exception rule changed.

## Semantic and checked-source evidence

`UserTransferScope` consumes the live `uname` entry while a copy is active and
returns exactly one refined successor. `CopyToUserComplete` records all 390
bytes; `CopyToUserFault` records the 256-byte prefix before the qualification
guard page. Reuniting that outcome with the entry produces result zero or the
x86-64 Linux encoding of `-EFAULT`. Disposition while the scope is live is not
representable.

The sealed source dispatcher owns these six 65-byte NUL-padded fields:
`Linux`, `topal`, `7.2.9-topal`, `#1 Topal`, `x86_64`, and `(none)`. Source
checking rejects changed fields, missing or reordered fields, wrong PID or
exit status, wrong context identities, and a missing qualification marker.
The reference model additionally rejects wrong syscall order, candidate,
extent, prefix, result, UTS value, and transfer identity.

## Initial x86-64 lowering

Provider and provider-object revision
`topal.provider.x86_64-qemu-pc-q35/17` and
`topal.provider-object.x86_64-qemu-pc-q35/17` add one generated byte-copy loop
and private page-fault entry. Before the copy, the provider records the exact
generated store site and recovery continuation in sealed per-context state.
IDT vector 14 accepts recovery only when:

- the generated user-copy scope is active;
- the fault is the expected non-present supervisor write;
- the saved instruction is the registered generated store; and
- `CR2` names the qualification guard-page boundary.

The entry replaces only its private saved continuation, clears recovery
authority, discards the x86 error code, and returns to the generated recovery
path. Any mismatch enters the fatal halt. The recovery path records the copied
prefix and returns Linux `-EFAULT`; the success path copies the complete
structure. Target registers, vector, error code, `CR2`, frame, instruction
addresses, and `IRETQ` remain provider-private.

Boot-adapter revision `topal.boot-adapter.linux-x86-protocol-2.15-q35/6`
installs the private vector-14 gate. Root-object revision
`topal.systems-root-object.x86_64/17` has 864 typed relocations. Artifact
revision `topal.systems-artifact.x86_64-qemu-pc-q35/17` records 50 provider
operations, 50 inspected placements, and a 139-transition semantic trace.

## Remaining boundary

The scope is still one qualification-only process, thread, address space,
layout, and kernel-to-user direction. It does not add `copy_from_user`, dynamic
user mappings, concurrent mapping changes, demand paging, general UTS
namespaces, ELF loading, file descriptors, signals, process creation,
scheduling policy, SMP migration, or a Linux userspace distribution. Those
remain dependency-ordered increments toward the complete pinned interface.
